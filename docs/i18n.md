# Languages

How the app picks and loads a language, moved out of `CLAUDE.md` on 2026-11-07 (#124). The rules every
task must obey (all text through `T`, nine languages, gender-neutral wording, the "never" lines below)
stay in `CLAUDE.md` → i18n.

## The browser's until the person picks one (2026-10-22)

`LanguageContext`: the saved choice, else the first of `navigator.languages` the app has
(`pickLanguage` in `src/utils/languages.ts`: `es-MX` → es), else English. **The detected
language is never saved**: only a person's pick is (`setLang`), so a browser that changes
its language changes the app. `fromBrowser` says when the language shown is the detected one
(the welcome says so). The language list with native names is `LANGUAGES` there; do not keep another.

- **The first paint is already in the person's language on the app's pages (2026-10-23).** A
  pick is also written to the `app-language` cookie (a year, `languageCookie`; a choice saved
  before the cookie existed is copied into it). `(main)/layout.tsx`, which is dynamic anyway (it
  reads the session), calls `serverLanguage()` (`src/lib/serverLanguage.ts`: the cookie, else
  `Accept-Language`) and wraps the page in a `LanguageProvider initial={…}`, which renders that
  language on the server and while hydrating, so they match. That covers the landing and the
  whole signed-in app.
- **Each language is its own chunk (2026-10-30, audit PERF-02):** `loadMessages`
  (`src/translations/load.ts`) imports it on demand; only English is in every page. A language
  must stay plain data, as `(main)/layout.tsx` sends the active one to the client as `messages`
  so hydration needs no fetch (`load.test.ts` fails on a function). Never import `es`, `pt`… into
  client code.
- **Do not call `serverLanguage()` (or `headers()`/`cookies()`) in the root layout**: it would
  make every page dynamic, the static ones too (`/privacy`, `/terms`, `/compare`, `/track`,
  `/welcome`). `/authPage` is dynamic on purpose: it reads `searchParams` on the server, because
  `useSearchParams` would send it empty. Those still paint English until they hydrate; reached by a client
  navigation (the usual way) they are already in the right language.
- `/privacy` lists the cookie among the necessary ones, in all nine languages.

## Adding a language

Not started; ask the owner which languages first (`roadmap.md`). Today nine (`LANGUAGES` in
`src/utils/languages.ts`); the browser's language is taken when it is one of them, so a new
language reaches its speakers on its own. A new one needs: its `src/translations/<lang>.ts`
(typed as `Translations`, every key), its entry in `LANGUAGES` and in `LanguageContext`'s
map, the texts kept outside `T` (`vaultGuide.ts`, `vaultGuideMore.ts`; the public pages fall
back to English), plural rules if it has its own (`T.plurals`), and gender-neutral wording.

## Vocabulary: one name per thing (#122, 2026-11-09)

The audit (CP-05, 07, 11, 13) found one thing under three or four names. These are the words; a new text uses
them, in every language. `src/translations/copy.test.ts` holds the ones that can be tested.

| Thing | English | Spanish | Other languages |
|---|---|---|---|
| Link a platform | **Connect** / Disconnect (toasts: connected / disconnected) | **Conectar** / **Desvincular** (progress: Conectando… / Desvinculando…) | the verb each language's own buttons already use (de verbinden/trennen, fr connecter/déconnecter, it collegare/scollegare, pl połączyć/odłączyć, pt ligar/desligar, ru подключить/отключить, ja 連携/連携を解除): buttons, toasts and hints say the same one |
| RetroAchievements | "Connect RetroAchievements"; **never "sign in"**: its key proves an account exists, not whose it is | Conectar RetroAchievements | same verb as the row above |
| PlayStation | "PlayStation" on buttons, "PSN" only for the online ID | idem | idem |
| The list of games | Library (the owner's "vault" is the whole site: `userPage.library` is "Your vault") | **biblioteca** (never "librería", which is a bookshop), "bóveda" only where English says vault | |
| Points | Vault Points | **Puntos Vault** everywhere | |
| A game you have not started | **Not started** | **Sin empezar** | |
| In progress | In progress | **En progreso** (not "En curso", which stays for a streak that is on) | |
| Pinned goals | **Achievements to get** (add to / remove from) | **logros por conseguir** | `favorites.title` is the name in each language |
| Mastery | Mastered | Maestrías (the noun), Masterizado (the status) | |
| Email | Email | **Correo** | |
| Steam's privacy setting | "Game details" | **Detalles del juego** (what Steam shows in Spanish) | |

- **Rank names are not people** (`rankings.tiers`): in es, it, pt, fr, de, pl and ru they are abstract nouns (Inicio,
  Aprendizaje, Caza, Veteranía, Pericia, Maestría, Gran maestría, Leyenda), so no reader is addressed as a man.
  English and Japanese were already neutral. `copy.test.ts` refuses the old masculine ones.
- **Em dashes**: none in a live string. The pause is a colon, a comma, parentheses or a full stop; in lists of
  facts it is the middle dot. Russian keeps its dash where it is punctuation (the copula: "Каждый квадрат — день").
- **Errors and codes**: a route sends a code; the text is `T`'s (`src/utils/apiErrors.ts`). See CLAUDE.md → API calls.
