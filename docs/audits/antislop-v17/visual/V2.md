# V2 — Library lists and game pages
Summary: The game pages already feel like one product at the top: the same `GameHero` (cover, chips, italic display
title, progress, facts, actions, tiles, two pictures), the same tabs, search, sort and "Mostrar los N restantes". They
come apart below the hero: each platform's table puts the pin star, the date and the "earned" signal somewhere else,
and the icon frame means something different on each platform. The lists (status pages, master-detail) are well
structured and calm in the rows; the noise is in the detail panel and on `/allGames`, an older page that does not look
like the rest. Three things make these screens read vibecoded: **colour used as decoration on data** (every stat value
its own hue, playtime in the platform's brand colour, "finished" in three different colours), **the slant applied at
five different angles and only to some controls in the same row**, and **boxes inside boxes with uppercase tracked
labels** in the detail panel. At 2560 the game table runs the full width, so a row's figures sit ~1,800 px from its name.

**Capture caveat (read first):** in my area the `round` shots are byte-identical to the `slanted` ones (md5 equal for
`allGames`, `completed`, `playing-console`, `notfound-game`, every `game-*` at 2560 and Steam/PSN/Xbox at 390;
`playing` and `game-ra__390` differ only in loaded data; crops `crops/V2-toolbar-slanted.jpg` vs
`crops/V2-toolbar-round.jpg`, `crops/V2-ra390-top-*.jpg`). The likely cause: `shape-style` is a synced key
(`src/utils/syncedPreferences.ts`) and `usePreferencesSync` applies the account's value over the browser's on sign-in
("the account wins"), undoing the `localStorage` the capture script set. So **round in the signed-in app was not
captured**; my round notes below come from the tokens, not from pixels. Recapture with the account's preference set to
`round` (or `PUT /api/preferences`) before judging round here. Also: `game-xbox` shows the "game not found" screen (no
Xbox game page to compare) and `notfound-game` shows a raw RA error, not the not-found screen (see V2-09).

### V2-16 · MED · slanted (one toolbar, two shapes)
- **See:** `crops/V2-toolbar-left.jpg` (search field and filter pills straight) vs `crops/V2-toolbar-right.jpg` (sort select a slanted parallelogram, segmented control with a slanted thumb in a straight track)
- **What:** in the same toolbar row half the controls lean and half do not. On the game page the search is straight and the "Orden del juego" select is straight-ish (`crops/V2-ra-toolbar.jpg`), while the hero's buttons above it lean.
- **Why it matters:** this is a nameable cause of "slanted feels strange": the slant is attached to *some components* (Button, Select-as-button, SegmentedControl thumb, chips), not to *a role*, so neighbours disagree.
- **Code:** `ui/` tokens `--slant-button`, `--slant-pill` (`globals.css:102-106`); `Pill`/`pillClass`, `SearchInput`.

It keeps the slant meaningful (= action) and stops toolbars looking half-converted.

**What really differs on the game pages (RA, Steam, PSN: the same list on all three):**

  circles in round, rounded squares in slanted (`r-v2-ra-hero-s.jpg`, `r-v2-st-hero-s.jpg`);

**What stays identical:** the hero's layout, cover, title (display italic), facts, the screenshot tiles and stat tiles, the table (rows, icons, columns, checks,

and the large surfaces stay soft rectangles, so it reads as friendly, not as a rounded-button template. But it has no idea of its own beyond that.

## Cross-cutting patterns seen
1. **Colour on data instead of on state** (V2-04, V2-05, V2-19, V2-13): values, consoles, playtime and "done" each get their own hue; one meaning per colour would remove most of the noise on these screens. Platform hue should live in exactly one place per screen: the platform chip.
2. **The same piece drawn per platform** (V2-01, V2-05, V2-11; D1-01, D2-01): the hero proves a shared piece works; the table, row, phone card and status card are the next ones to share, and that sharing is what fixes the visible drift.
3. **Ornament that repeats a fact** (V2-02 ✓ + date, V2-13 100 % bars, V2-06 "Sin datos", V2-10 "Captura 1", V2-20 kicker = H1): cut the second signal.
4. **Boxes in boxes with tracked-caps labels** (V2-15): the hero's plain facts are the house style already; use them in the panels.
5. **Width at 2560** (V2-03, V2-18): full-width tables and cards leave the data stranded; one max width on content.
6. **Error and empty states diverge by platform** (V2-09): RA's game page has its own raw error while the others share designed screens.
