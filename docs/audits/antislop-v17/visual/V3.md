# V3 — Social and progress pages (groups, following, rankings, streak, public profiles)

Summary: These pages work and the data is real and specific (real covers, real achievement icons, real
numbers from four platforms), which is the best thing they have. Three things make them read vibecoded.
(1) **The same thing is said two or three times on one screen**: counts in the hero and again in the tabs,
the profile's identity in the hero and again in a card, the same three achievements in "Logros recientes",
"Últimos logros" and the showcase, progress shown three times on a game. (2) **Gamified decoration piles up**:
tier badges in eight hues, streak bars in tier hues, gold/silver medal numbers, the level ring, `Nv. 31` and
`56 d` chips in the header on every page, Beta three times on one page. Together they turn into a "gamified
dashboard" look. (3) **The same idea is drawn several ways**: a person, a level, a section heading, a tag and a
stat tile each have three to seven looks (the code report already counts them: B-08, B-09, B-11, B-22). The
slanted design is applied piecemeal (some tags, some buttons, some chart bars), with angles that change with the
element's height.

**Capture note (important for the round/slanted pairs):** every `app/` pair in this area is pixel-identical
at 2560 (diff 0.000 %, measured with sharp). The 390 diffs (≤4 %) are load timing. Round was never applied to
the signed-in shots, almost certainly because `usePreferencesSync` applies the account's `shape-style` over the
`localStorage` value set by `.audit/capture.js` ("the account wins"). The round comparison below therefore uses
the signed-out pages in this area that did change: `public/rankings-public`, `public/rankings-how` and
`public/profile-teaser`. The app pairs should be retaken with the account's preference set to round.
